## Initial rendered graph evidence

Route: `/scans/nodejs-goof`, real stored `snyk-labs/nodejs-goof` scan at `add14ba59e98`. Input snapshot: 996 graph nodes, 1,694 edges, 140 vulnerable components. Matching findings are component/finding occurrences, not a globally unique CVE count.

A matrix captured **12 states at each of 1440×960, 768×1024 and 375×812**: overview, strict vulnerable mode, KEV, high+KEV, empty search, reset, group expansion, transitive expansion, details, retained selected path, minimap, minimap click. Captures and structured traces are local QA artifacts, intentionally not committed. Capture dimensions were checked from the PNGs, and state counts were deduplicated programmatically.

Observed:

- Default overview shows 4 repository/project nodes, not the entire graph at a tiny scale.
- Strict mode shows 140 vulnerable components; KEV reduces it to 2, and high+KEV to 1. The desktop camera moves from 17% to 98% to 100%, rather than leaving the filtered result tiny.
- Empty search yields 0 matches and a reset affordance. Reset restores the overview.
- Dockerfile expansion adds its image (5 nodes); expanding that image adds its process (6); collapse restores the overview. Narrow maps use zoom-dependent expansion controls.
- The selected Node.js dependency context has 4 nodes. Desktop uses a vertical chain at 90%; smaller views focus the selected component when fitting all ancestors would make labels unreadable.
- Closing details, including Escape, retains the selected path. Mobile map/list switching does not leave the list hiding the map below the fold.
- Minimap clicks moved the viewport at all three widths; a separate drag probe observed movement before mouse release. The minimap remains bottom-right and reserves navigation space.
- Far-zoom repository summary retained the 140-vulnerable-component aggregate instead of becoming an uninformative glyph.
- Enter activated a focused risk row. Reduced-motion navigation was exercised separately.
- No document-level horizontal overflow or observed page errors/failed resource responses in the recorded matrix. This is bounded observation, not exhaustive network/SSE testing.

## Interaction budget, not field performance

In an active, unthrottled local 1440×960 browser with the graph loaded, two explicit warmup toggles were followed by eight filter toggles. The largest measured DOM-update time was **5.6ms**, and the largest click-to-two-animation-frames sample was **65.2ms**, within the 200ms warm diagnostic target.

Initial/warmup paint samples also exceeded 200ms and are retained in the trace. The follow-up separated DOM mutation from animation-frame scheduling and observed no long tasks in those samples. This does not establish a cold-start, field-INP or p75 guarantee, and it does not prove a speedup over the previous UI.
