# v0.1.0 release scope and publication gates

## Scope

First public pre-1.0 release. Include the existing working-tree fixes, the shared scan engine/CLI, provider and storage boundaries, remediation executor separation, parser/error hardening, and the approved large-graph triage UX. Preserve API/persisted shapes and approval-before-push behavior. The standalone `jinho-yoo-jack/cassandra-action` repository contains only the download/scan adapter, documentation, tests and license; it does not duplicate the engine.

Version surfaces: service/CLI and standalone Action start at `v0.1.0`; the CLI embeds `0.1.0` in its version output/SBOM. Action defaults to the exact CLI release, not `latest`. No existing public tag is moved or reused.

Excluded: automatic remediation in the Action, new backend service boundaries inferred from graph layout, multi-tenancy/auth changes, and exploitation/reachability claims.

## Gates and order

| Stage | Cohort | Promotion signal |
|---|---|---|
| Local freeze | this checkout | complete tests/builds, secret scan of publication candidates, independent review, real large-graph QA at 1440/768/375 |
| Main CI | exact committed service SHA | GitHub CI success read back for that SHA, no intervening changes before tagging |
| CLI release | v0.1.0 assets | release workflow success, exact remote tag target, assets/checksum download and executable smoke tests |
| Action consumer | standalone repo CI using `uses: ./` | real GitHub runner consumes published CLI, clean exit 0 and vulnerable exit 1, outputs and artifacts checked |
| Marketplace | Action v0.1.0 | name/metadata/category validation, account agreement/2FA requirements met, listing URL read back and usage reference verified |

Artifact distribution has no meaningful traffic percentage or timed canary. Promotion is gated by a real consumer workflow, not a blind waiting period. Do not mark Marketplace publication complete from a GitHub Release alone.

## Stop/containment procedure

Before initial promotion, any failed required test, bad checksum, incorrect scan exit code, missing consumer artifact or unresolved review blocker stops the next stage. Do not tag an unverified commit.

If a newly published CLI fails its first download/consumer check or a confirmed unsafe behavior is found before Marketplace promotion, stop promotion and quarantine its release (repository owner/operator):

```sh
gh release edit v0.1.0 --repo jinho-yoo-jack/Cassandra --draft
```

If the Action release itself is unsafe, stop Marketplace promotion and quarantine it:

```sh
gh release edit v0.1.0 --repo jinho-yoo-jack/cassandra-action --draft
```

Read back `isDraft` after either command. If already Marketplace-listed, uncheck its Marketplace publication on the release page and verify the listing separately; changing draft status alone is not claimed to delist it. Never delete/reuse a published version or force-move its immutable tag. Fix in a new patch release. Downloaded copies cannot be recalled.

## Authentication boundary

GitHub CLI authentication can create repositories, push and publish releases within the user's approval. Marketplace agreement and two-factor requirements are separate account checks. Passwords/codes never go through chat or shell. If an authenticated browser cannot be obtained, finish independently authorized repository/release work and report the exact Marketplace blocker rather than claiming a listing exists.

## Publication evidence

Populate actual commit, workflow, release and listing URLs only after readback. Local preparation is not a published release or Marketplace listing.
